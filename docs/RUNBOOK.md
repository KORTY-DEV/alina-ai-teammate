# Безопасный запуск MVP

## 1. Проверка исходников

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Test-Project.ps1
```

Скрипт использует отдельные каталоги под `.test-output`, собирает .NET bridge, запускает контрактные тесты и проверяет загрузку Lua-мода движком 2.1.12. Реальные сейвы и `AppData\Roaming\Factorio\mods` не изменяются.

Нагрузочный тест Ollama по умолчанию отключён. Его можно включить отдельно только когда не запущена игра, FPS которой важен:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Test-Project.ps1 -IncludeOllama
```

Полный E2E использует только `.test-output` и сам закрывает созданные процессы:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Test-VerticalMvp.ps1
```

Он откажется стартовать, если уже запущена Factorio, чтобы не закрыть пользовательскую сессию и не смешать замеры.

## 2. Подготовка конфигурации bridge

```powershell
Copy-Item .\bridge\appsettings.example.json .\bridge\appsettings.local.json
$env:ALINA_RCON_PASSWORD = '<случайный-локальный-пароль>'
```

Пароль не нужно записывать в репозиторий. RCON должен слушать только `127.0.0.1`.

## 3. Установка мода

Установка меняет реальный список доступных модов, поэтому она не выполняется автоматически. После проверки диффа запустите:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Install-DevMod.ps1
```

Скрипт откажется работать при запущенной Factorio, проверит конечный путь и сделает резервную копию предыдущей версии `alina-ai-teammate`, если она есть. Существующие сторонние моды и модели Ollama он не трогает.

## 4. Игровой transport

Текущий надёжный transport — локальный сервер:

1. локальный headless-сервер открывает игровой порт и RCON только на loopback;
2. обычная Factorio подключается к `127.0.0.1` как клиент;
3. bridge читает `script-output` сервера и отправляет планы через RCON.

До первой установки это нужно испытать на копии сейва. Нельзя направлять сервер на единственный экземпляр важного сохранения.

## 5. Bridge

```powershell
dotnet run --project .\bridge\Alina.Bridge --configuration Release -- --config .\bridge\appsettings.local.json
```

Bridge не скачивает модели. Если `qwen3.5:4b` отсутствует, он завершится с понятной ошибкой.

## Команды MVP

- обычный чат: `Аля, добудь железа`;
- диагностика: `Алина, железа не хватает, разберись`;
- `/alina-spawn` — восстановить персонажа;
- `/alina-status` — состояние и счётчики;
- `/alina-export-catalog` — порционный экспорт реальных прототипов;
- в GUI: пауза, продолжение, стоп.

Примеры локальных фраз без вызова LLM: `Алина, остановись`, `Аля, продолжай`, `Алина, здесь ничего не трогай`.

## Известные границы 0.1.0

- playable MVP строит связанные item- и fluid-блоки, использует существующие хранилища/машины, длинные ленты, трубы, насосы, питание, роботов и проверяет фактический выпуск;
- автономный цикл использует World Model, production flow, активные рецепты и связи потребителей; при прямой команде развития он сначала пытается безопасно расширить/улучшить существующее, затем строит полный mod-aware блок одного из полезных уже присутствующих продуктов;
- обычные расходники берутся только в normal quality; качественные предметы и машины не расходуются и не заменяются автономно;
- полное управление поездами, планетами и крупной военной стратегией сознательно отложено; рельсы в этом MVP покрывает только безопасное пересечение;
- K2SO проверен на побитовой копии реального сохранения, однако длительная автономная валидация всех поздних производств K2SO/Cerys/Moshine ещё не завершена;
- перед публичным релизом всё ещё нужны длительные ручные игровые сессии и multiplayer с несколькими реальными игроками.
